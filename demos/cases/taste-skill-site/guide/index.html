How to brief the skill.

How to call it in your agent, prompts to copy for a new page, a redesign or review and an app screen, and the facts that get a page built for your client instead of the category.

Read the docs

Calling the skill

Once installed, the skill loads by itself when you ask for a page, a redesign or an app screen: its description tells the agent when to use it. Naming it in the prompt makes sure, and keeps another design skill from being picked instead.

Claude Code

Ask in plain words, or type /design-taste-frontend to call the skill directly. Installed as a plugin, it is /taste-skill:design-taste-frontend.

Codex

Start a new session after installing. Mention the skill with $design-taste-frontend, or pick it from /skills.

Cursor

Install with the skills CLI. The agent picks the skill up from its description; to be sure, name it in the prompt: “use the design-taste-frontend skill”.

Other agents

OpenCode, Gemini CLI and any agent that reads SKILL.md files: name the skill in the prompt. The agent needs to run commands in your project, because the draw, the picture search and the inspector are Node scripts.

Not installed yet? The install section has every method.

A new landing page

Give the facts, not the look. The skill deals the direction itself, so words like modern or premium add nothing. What it needs is what only this client has.

Prompt: new landing page
Use the design-taste-frontend skill to build a landing page.

Client: [name, and what the name means]
What it is: [what it makes, sells or does, and for whom]
Place: [street and number, neighbourhood, city, or "online only"]
The one action: [book a table, order beans, start a trial], which goes to [URL, email address or checkout]
Facts: [prices, opening hours, dates, seats or sizes, the year it started]
The constraint it lives with: [one batch a week, closed in winter, by appointment only]
Content the page must carry: [the full menu with prices, the rooms, the line-up, the plans, real questions]
Our own pictures: [folder path, or "none"]
Brand: [colours, fonts, logo file, or "none yet"]
Stack: [plain HTML, or the framework and folder of an existing project]

Run the whole skill: the inventory, three dealt directions and which one you chose and why, the idea sentence, real pictures with their credits, lint.mjs and inspect.mjs until there is no FAIL at 1440, 768 and 390, and up to three look-and-fix rounds. Then give me the report.

Replace the brackets and drop any line you cannot fill. The agent fills gaps such as dish names or room rates with sample details and lists them for you to confirm. It never invents customers, quotes, reviews or business figures.

Redesigning a page

The skill keeps your stack, your content and what works, and proves the change with before and after measurements. Tell it what must survive and how far to go: a restyle keeps the layout, a redesign rebuilds the sections.

Prompt: redesign
Use the design-taste-frontend skill to redesign [the page or route] in this project.

It runs at: [http://localhost:3000/pricing, or the built index.html]
Scope: [restyle: keep the layout, change type, colour and components] or [redesign: deal a new direction and rebuild the sections]
Must stay: the stack and styling method, the routes, the forms and what they send, [logo, brand colours, legal copy, anything else]
What is wrong today: [in your own words: hard to read, looks like a template, weak on a phone]
Our own pictures: [folder path, or "none"]

Record the before first: inspect the running page into .taste-skill/before and lint the source. Then work in the skill's order (type, colour, the frame, states, stock components), inspect again into .taste-skill/after, click through every link, form and menu that worked before, and report the before and after measurements side by side.

For a review without any changes, it stops after the before:

Prompt: review only
Use the design-taste-frontend skill to review [the page] at [URL]. Do not change any code.

Inspect it into .taste-skill/before, critique the screenshots with references/critique.md, list the findings with the inspector's measurements, and name the three changes that would move the page most.

An app screen or dashboard

Dashboards, admin views, settings and inboxes take their own route, with their own styles and checks. Say that it is an app screen, describe the data and the job, and give it real data if you have some. The route is written in app-screens.md.

Prompt: app screen
Use the design-taste-frontend skill to build an app screen, not a landing page: the [overview, list, detail or settings] screen of [product].

Who opens it: [role], [a glance each morning, or all day], on [desktop, phone or both]
The data: [the objects and their fields with units, and realistic sizes: about 40 orders a day, 18 to 240 euros each]
Data file: [path to real or exported data, or "write a realistic dataset whose totals add up"]
The screen's one question: [Did today's orders ship?]
The job people do most from here: [print the labels for the orders due today]
Theme: [light or dark]
Brand: [colours and font, or "none"]
Stack: [the framework and folder, or plain HTML]

Follow the app-screen route in references/app-screens.md: deal a style with draw.mjs --app, build the shell, the data and the empty, loading and error states, check with inspect.mjs --app at 1440, 768 and 390, and give me the report.

Each screen answers one question first, and the largest block on it carries the answer. Totals are computed from the rows, so the figures on the screen add up.

What makes a good brief

Before it designs anything, the agent lists eight to twelve things that belong to this client and to no competitor. In the skill's blind tests the page that won each brief was built from such an item. The more of them your brief holds, the less the agent has to guess:

  • The real name, and what it means if it means something.
  • The place: the street and door number, the neighbourhood, what it looks like.
  • The numbers: seats, rooms, minutes to the sea, the price, the year it opened.
  • The constraint it lives with: one batch a month, closed in winter, by appointment only.
  • Its rituals and hours: the oven lit at five, the last ferry at seven.
  • Its materials and printed things: the tiles, the label, the ticket, the timetable.
  • Your own photographs, and the folder they are in. Pictures of your own beat anything found.
  • The one action the page must get, and where it goes: a booking link, an email, a checkout.

The same request, thin and then usable:

Thin
Make a modern, premium landing page for my bakery.
Usable
Use the design-taste-frontend skill to build the landing page for Sete Portas, a bakery named after the street it stands in. 14 seats. The oven is lit at five, the bread is out at seven and usually gone by noon. Closed on Sundays. One sourdough at 6 euros and three pastries; the full list with prices is in menu.md. Our own photos are in ./photos. The page should get people to pre-order for Saturday by email.

What to expect

Time and tokens

Roughly 30 to 45 minutes and a few hundred thousand tokens for a full run with the look-and-fix loop. Most of it goes into finding or drawing pictures when the project has none.

Few questions

The agent asks only when a missing fact blocks the work, such as no product name. Otherwise it states its reading of the brief in one line and goes on.

Files in your project

The direction sheet and the inspector's screenshots at 1440, 768 and 390 in .taste-skill/, downloaded pictures in assets/ with their credits in assets/credits.json.

A report at the end

The direction and any redraws with reasons, the idea and the live thing, its last scores and what still falls short, every found picture with its licence and where its credit sits, and the sample content to replace.

Common problems

Claude Code says “Unknown skill”.

Versions 2.1.0 and 2.1.1 had a frontmatter bug that stopped the skill loading in Claude Code. Run the install command again, or /plugin update for the plugin.

An older skill ran instead.

Since 2.1.1 the classic skills run only when called by name, and since 2.1.3 they live in a separate repo. Update, and name design-taste-frontend in the prompt.

The inspector cannot find a browser.

Install Chrome, Edge or Chromium, or set CHROME_PATH to the browser's executable. The inspector also needs Node 22 or newer.

The page has few pictures or barely moves.

The inspector fails a page with fewer than four real pictures (few-pictures) or fewer than eight moving elements (still-page). Ask the agent to run the gate and fix every FAIL before it reports.

It still looks like the category.

Give it more of the inventory. A brief that could describe any bakery gets a page that could belong to any bakery; the idea comes from the facts only your client has.

The build looks different from the dev server.

Bundlers change the CSS a visitor receives. Ask for the last check on the production build (next build && next start, vite build && vite preview); the inspector warns when it sees a dev server.

My temp folder is filling up.

Those are the inspector's browser profiles. Update to 2.1.4 or later, delete old ad-chrome-* folders by hand, and set TASTE_SKILL_TMP to keep them off the system drive.

The agent has no network.

assets.mjs cannot reach the collections, so the agent draws the pictures and says so in the report. Your own photographs fill the gap best.
